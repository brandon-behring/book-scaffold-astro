### A vs B: corrected cost model

A code-grounded review revised the implicit lean in `PACKAGE_DESIGN.md` §15a. Both options were mis-costed.

**A — corpus-as-monorepo** (one app, namespaced books, one build; graduates recipe 21):

- **Routing is not a "dispatcher refactor."** Route *injection* is centralized — a `ROUTE_REGISTRY` + a single dispatch loop (`package/src/integration.ts:133–175, 268–277`) — so emitting `/<book>/` patterns is a one-place change. The navigation *hrefs* into `/chapters/…` are **not** centralized, though, and all need the same prefix (enumerated under tooling below).
- **Schema is not a "Zod union restructure."** The per-profile schemas are standalone, switched at registration (`package/src/schemas-entry.ts:131–136`) — there is no runtime union. Adding `book` is an additive optional field, stageable behind `multiBook: true` (default-off) so single-book consumers stay byte-unaffected.
- **The real cost is the build/validation tooling and the scattered hrefs** — the part the design doc never names: `package/scripts/validate.mjs` (≈5 of its 9 checks assume a flat id space), `package/scripts/build-labels.mjs` (chapter counter **plus** its `/chapters/…` label hrefs), `package/scripts/build-exercises.mjs`, `package/scripts/build-tips.mjs` (flat keying), the hard-coded `/chapters/…` hrefs in the index pages + `WeekRef.astro` + `exam-manifest.ts`, plus the `getStaticPaths` reshape `{slug} → {book, slug}` in `package/pages/chapters/[...slug].astro`. Bounded, owned, well-tested — unglamorous but tractable.

**B — corpus-as-federation** (independent per-book builds stitched under `/<book>/` via Astro `base` path-proxying):

- Its premise ("reuse the v4.24 base-aware work") is **half-true**: #140/#141 made *some components* base-aware but left the **route pages** *and* the label/`XRef`/`WeekRef` href path root-absolute (both folded into #142).
- It needs net-new, undesigned subsystems: a corpus-wide Pagefind index (the build is `pagefind --site dist`, per-book only), a corpus landing / book-selector, and cross-book base-prefixing + Phase-2 link validation (`package/src/lib/book-link.ts:13–15, 16–31`).

**Why A, not B:** the two consumers that fired the trigger are *already* on the single-app pattern. **A graduates what they do; B would ask them to re-architect.** B's lone advantage — independent book lifecycles / separate repos — answers a *different, unfired* need (a future "guides hub" federation). B is recorded as a separate, deferred track; its only no-regret slice (finishing route-page base-awareness, #142) ships now regardless.

## Interactive demos (#103) — volatility split

Three consumers hand-roll demo islands (guides, guides-ai-engineering's ~9, double_ml_time_series); the event hook (`book:theme:change`) already shipped (v4.14.2). Rather than graduate the whole kit or keep deferring it, split on the volatility seam — the same lens the tools profile applies to T1–T4 *sources*, turned on the *API* surface:

- **Graduate now (v4.x), tracked in #143:** the stable substrate — `DemoFrame` shell, generic controls (`Slider`, `StatCards`), a `useThemeColors` wrapper over `book:theme:change`, and the a11y / reduced-motion / SVG-theming plumbing + `demo.css`. This is the consumer-agnostic chrome where the duplication tax lives, at near-zero API-lock risk.
- **Keep incubating in DML (#103):** the domain kernels (OLS, residualize, sampling sims) and opinionated viz (`ScatterFit`, `SamplingDistribution`), whose API is still proving out. They graduate mechanically once stable.

## Sequencing rationale

Order within the v4.x line is **consumer-signal density**, not size: #142 first (a live bug for the path-proxied consumers), then #143 (three consumers paying the hand-roll tax); #144/#145 stay warm and ship on author signal; #83 is consumer-local and parallelizable. The v5.x gate opens **in parallel** — it is a design/writing task, not contending with v4.x implementation bandwidth — and implementation waits on scope-doc approval, preserving the repo's design-before-invasive-code discipline. Releases stay user-gated; nothing here bumps a version or tags.
