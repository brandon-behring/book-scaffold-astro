## 3. Code findings (C)

### C1 (P2) — `resolvePreset` silently defaults to `'minimal'`

`package/src/types.ts:425-436`: when no preset is set anywhere (param → env → .env), it falls back to `'minimal'` with only a `console.warn`. An *invalid* value **does** throw (`:427-431`) — the gap is only the unset case, and it is documented as resolution step 7 (`:404`). Still, it's the sole exception to the codebase's otherwise-codified fail-loud stance (`assert-prop.ts`, throw-on-missing-`site` `config.ts:104-109`, throw-on-unknown theorem/book/domain). A consumer whose `.env` is missing in CI silently builds the wrong profile. Recommend: throw, or make the fallback an explicit opt-in.

### C2 (P2) — the `deploy` config option is inert despite its docs

`package/src/types.ts:81-86` documents `deploy` as "drives create-book's wrangler.toml shape … a per-book override here beats any style. Closes #50." Reality: `config.ts:255,286` strips it unused (`void _deploy`); `define-style.ts:218` merges it into the composed style but nothing reads the merged value (verified: sole `.deploy` reference in `src`/`scripts`/`bin`); `create-book.mjs:115` derives Pages-vs-Workers purely from the profile name at scaffold time. A consumer setting `deploy: 'pages'` on an academic book gets no change and no warning. Wire it or un-document it (fail-loud would argue for throwing on the unsupported override until it works).

### C3 (P2) — create-book undercounts its own presets; scaffolds ship frozen doc links

Verified at runtime: `--help` prints `--preset=NAME academic | tools | minimal` and an invalid preset errors with `must be one of academic | tools | minimal` (exit 2) — yet `--preset=course-notes` scaffolds successfully (exit 0; `VALID_PROFILES` at `create-book/bin/create-book.mjs:79-85` accepts 5). Users of the two newest profiles can only discover them from external docs. Additionally, scaffolded output hardcodes PACKAGE_DESIGN links to the frozen `blob/v3.0` branch (`:239,:269,:481` → generated `CLAUDE.md`, `README.md`, `sources/manifest.yaml`), so every fresh v4.26 book self-documents against v3.0-era API docs.

### C4 (P3) — BASE_URL normalization: 18 inline sites, 3 idioms, no shared helper

Census (`.astro` layer): 14 files use `.replace(/\/?$/, '/')`, 3 use `.replace(/\/*$/, '/')` (`Base.astro:120`, `Sidebar.astro:25`, `NavContent.astro:29`), 1 uses `.replace(/\/+$/, '')` (`Rationale.astro:51`). **Triage verdict: no correctness bug** — the Rationale outlier is deliberate and correct (strips the trailing slash to compose `${basePath}/answers`), and the first two idioms are equivalent on Astro's `base` shapes. This is a consistency/maintainability finding: the pre-compiled-dist constraint (documented at `src/lib/exam-manifest.ts:55`) rules out a lib-side `import.meta.env` read, but a shared `.astro`-layer helper or a param-taking lib function (the existing `lib/nav-href.ts` pattern) would collapse 18 copies to 1 and end the idiom drift. Distinct from the base-awareness *bug* lineage (#140/#142 closed via #155; #168 still open for `pages/chapters.astro`).

### C5 (P3, informational) — reserved surfaces, documented as such

`cloze` question type is schema-accepted, render-deferred (`schemas.ts:410-413` — tracked as #144). `EvidenceTag`'s `source` prop renders as `data-source` with no behavior, reserved for a future fail-loud `validate.mjs` check (`package/CLAUDE.md`). Both intentional; listed so the report is complete.

### C6 (P3, informational) — soft-catch inventory

~26 catch-and-continue sites, nearly all intentional (browser guards, best-effort parsing in lint-style tools). Inventory in Appendix B; the validator swallow-sites are the ones worth revisiting when #175/#176 extend `validate.mjs`.
